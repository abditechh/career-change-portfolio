# Abdi Abdirashid — GitHub Presentation Pack

This pack reorganises the existing projects around one clear professional story:

> Industrial quality-control worker transitioning into IT support and software testing.

The language is deliberately simple and honest. It presents Abdi as a motivated beginner who needs to maintain a stable income while learning—not as an experienced IT professional.

## Recommended GitHub structure

1. Create a public repository whose name exactly matches your GitHub username.
2. Put `profile/README.md` in that repository as `README.md`.
3. Create a separate `qa-portfolio` repository using the supplied QA starter.
4. Add the supplied project README to each corresponding existing repository.
5. Pin repositories in this order:
   1. `qa-portfolio`
   2. `job-application-tracker`
   3. `personal-portfolio`
   4. `drone-portfolio`

`MTF-trainee-personal-message.md` contains a simple, personal explanation of why the paid trainee opportunity is especially important.

## Important before publishing

- Do not publish your birth date, age, full address or telephone number on GitHub.
- Keep the attached CV as the primary application document.
- Use GitHub as supporting proof of learning and practical work.
- Add one screenshot to each project README.
- Confirm Firebase Authentication and Firestore security rules isolate every user's records before sharing the Job Tracker.
- A Firebase web API key is normally a client identifier rather than a password, but access must be protected through correct Firebase security rules and authorised domains.
- Do not upload the Drone Portfolio folder in its current form: it contains duplicated images and very large videos. Host videos separately or compress them first.
- Remove percentage-based skill claims. Describe what you can actually build, test or explain.
